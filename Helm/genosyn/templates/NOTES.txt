Genosyn {{ .Chart.AppVersion }} is rolling out.

1. Reach the app
{{- if .Values.ingress.enabled }}

   http{{ if .Values.ingress.tls.enabled }}s{{ end }}://{{ .Values.ingress.host }}
{{- else }}

   No Ingress is enabled. Port-forward to try it out:

     kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "genosyn.fullname" . }} 8471:{{ .Values.service.port }}

   then open http://localhost:8471. For real use, set ingress.enabled=true
   and ingress.host (WebSockets pass through a plain Ingress rule).
{{- end }}

2. First boot

   The pod becomes Ready once every database migration has run — /api/health
   answers only after boot completes, so a pending readiness probe during the
   first minute is normal. Create the first account in the browser; the first
   verified sign-in becomes the master admin. Then review the public URL at
   Admin -> General.
{{- if .Values.config.multiTenant }}

   multiTenant is ON (the chart default). Only
   {{ .Values.config.bootstrapMasterAdminEmail }} may claim the master-admin
   account — and multiTenant forces Secure session cookies, so the FIRST
   login must already happen over HTTPS: reach the app through the Ingress
   with TLS, not a plain http:// port-forward, or the browser will drop the
   session cookie.
{{- end }}

   System email (verification, invites, password resets) is NOT in this
   chart. Configure it after boot at Admin -> Email transport; it is stored
   encrypted in the database. Until then boot prints a warning and every
   such mail — including the bootstrap master admin's own verification link —
   is written to the pod log instead of being sent. Read it with:

     kubectl logs -n {{ .Release.Namespace }} deploy/{{ include "genosyn.fullname" . }}

   Paste that link into the browser to verify and claim the account, then set
   up SMTP from the dashboard.

3. Command execution (the coding sandbox)
{{- if .Values.sandbox.enabled }}

   sandbox.enabled=true (the chart default) — the pod requests
   seccompProfile Unconfined and procMount Unmasked{{ if not (kindIs "invalid" .Values.sandbox.hostUsers) }}, plus pod-spec
   hostUsers: {{ .Values.sandbox.hostUsers }}{{ end }}. Your cluster must support all of it:
   procMount Unmasked needs the ProcMountType feature gate, hostUsers: false
   needs UserNamespacesSupport (set sandbox.hostUsers=null on clusters
   without that gate), and Pod Security admission must permit the fields in
   this namespace (they are rejected below the `privileged` level). If the
   pod will not schedule, turn the sandbox off with the exact flags:
{{- if .Values.config.multiTenant }}

     # multiTenant refuses to boot without a working sandbox, so turning it
     # off means leaving multi-tenant mode — the self-host shape:
     helm upgrade {{ .Release.Name }} ... -f values-selfhost.yaml
     # or explicitly:
     helm upgrade {{ .Release.Name }} ... --set config.multiTenant=false --set sandbox.enabled=false
{{- else }}

     helm upgrade {{ .Release.Name }} ... --set sandbox.enabled=false
{{- end }}

   Genosyn then runs with command execution disabled and says why.
{{- else }}

   sandbox.enabled=false — Genosyn boots with command execution disabled and
   logs the reason. Chat, Routines, Integrations, and browser work all still
   function; builds, test suites, and per-employee checkouts do not. Set
   sandbox.enabled=true when your cluster can honor the required
   securityContext (see values.yaml).
{{- end }}

4. Data

   /app/data {{ if .Values.persistence.enabled }}is persisted on PVC {{ .Values.persistence.existingClaim | default (printf "%s-data" (include "genosyn.fullname" .)) }}{{ else }}is NOT persisted — persistence.enabled=false is only
   safe for throwaway evaluation{{ end }}. Keep the volume even on Postgres
   installs: it holds checkouts, browser state, and uploads.
{{- if not .Values.secrets.existingSecret }}

   The session/encryption secrets live in Secret {{ include "genosyn.instanceSecretsName" . }}
   (generated once, kept across upgrades AND `helm uninstall` — rotating the
   encryption secret would orphan every encrypted row). Back that Secret up
   with the database.
{{- end }}
{{- if .Values.postgres.enabled }}

5. Bundled Postgres

   postgres.enabled=true runs a single-node, untuned Postgres for evaluation.
   For production, operate your own Postgres and point
   config.db.postgresUrlSecret at it.
{{- end }}
